# FinX & Banking Partner UAT Test Matrix

This document defines the formal joint integration test scenarios between FinX and the banking partner sandbox environment. Each scenario must be executed and recorded before issuing production certification signoff.

| Test ID | Scenario | FinX Action | Expected Bank Result | Expected FinX State | Required Evidence | Pass/Fail | Notes |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **UAT-001** | Successful Settlement | Dispatch valid payout with operation key `FINX-REL-{id}` | Bank accepts transfer (HTTP 200/202), processes IMPS/NEFT, sends final success webhook with UTR | Initial: `SUBMITTED`. Final: `SETTLED`. Release reservation `CONSUMED`. Double-entry ledger balanced. | Provider response payload, signed webhook payload, valid UTR, balanced journal entry. | PENDING BANK UAT | Baseline happy path |
| **UAT-002** | Idempotent Duplicate | Dispatch exact duplicate request with identical idempotency key | Bank identifies replayed key, returns original transaction reference, does NOT execute second transfer | No second `ReleaseInstruction` created; original remains `SETTLED`; exactly 1 debit on bank account. | Bank duplicate ACK, account balance audit showing single debit. | PENDING BANK UAT | Verifies payment rail deduplication |
| **UAT-003** | Provider Timeout | Dispatch payout request; simulate bank gateway timeout (>15s) | Bank gateway drops connection or times out; transfer may or may not have reached clearing | FinX state transitions to `UNKNOWN`. Reservation remains `ACTIVE`. Outbox worker does NOT retry blindly. | Gateway timeout log, `SettlementExecutionAttempt` recorded as `AMBIGUOUS_TIMEOUT`. | PENDING BANK UAT | Critical safety guard against double payout |
| **UAT-004** | Unknown Result | Dispatch payout resulting in HTTP 500 / 504 gateway response | Bank records transaction in indeterminate state | FinX records `UNKNOWN` status. Funds remain reserved in escrow pool. Payout gate halts automatic resubmission. | Gateway 5xx response log, database state verified as `UNKNOWN`. | PENDING BANK UAT | Proves fail-closed isolation |
| **UAT-005** | Rejected Payout | Dispatch payout to synthetic test account configured for rejection (e.g. invalid IFSC) | Bank rejects transfer with explicit failure code (e.g. `ACCOUNT_CLOSED`, `INVALID_IFSC`) | FinX records `FAILED`. Escrow reservation cancelled/released back to available pool. No ledger debit. | Signed failure webhook / rejection response with reason code. | PENDING BANK UAT | Verifies clean failure handling |
| **UAT-006** | Duplicate Webhook | Bank sends identical success webhook event twice for same UTR | Bank delivery simulation | FinX processes first webhook to `SETTLED`; second webhook acknowledged HTTP 200 idempotently with zero duplicate ledger impact. | Webhook access logs showing 2x HTTP 200, database journal entries showing exactly 1 debit/credit pair. | PENDING BANK UAT | At-least-once webhook safety |
| **UAT-007** | Invalid Signature | Bank sends webhook with corrupted HMAC or mismatched signature | Simulated man-in-the-middle / signature mismatch | FinX webhook listener rejects event with HTTP 401/403. State remains unchanged. | Webhook rejection log (`INVALID_SIGNATURE`), audit log entry. | PENDING BANK UAT | Authenticity enforcement |
| **UAT-008** | Delayed Webhook | Bank settles transfer but holds webhook delivery for 30 minutes | Simulated webhook queuing latency | FinX background status recovery job polls bank status API, observes `SETTLED` with UTR, finalizes settlement ahead of delayed webhook. | Status query audit log, observation record created with source `STATUS_POLL`. | PENDING BANK UAT | Out-of-order recovery verification |
| **UAT-009** | Polling Recovery | Payout in `UNKNOWN` state resolved via status inquiry API | Bank status inquiry returns authoritative `SUCCESS` and UTR | FinX binds observation, transitions instruction to `SETTLED`, consumes reservation, posts ledger journal. | Status inquiry request/response log, transition audit trail. | PENDING BANK UAT | Recovers ambiguous outcomes cleanly |
| **UAT-010** | Statement Reconciliation | Bank delivers end-of-day statement file containing settled UTR | End-of-day CAMT.053 / CSV feed imported | `DeterministicReconciliationMatcher` correlates statement line to `ReleaseInstruction` by UTR, amount, and account. Marks `MATCHED`. | Reconciliation run report, `ReconciliationItem` state `MATCHED`. | PENDING BANK UAT | Full closed-loop 3-way reconciliation |
| **UAT-011** | Duplicate Finality Evidence | Both valid webhook AND status poll AND statement feed report settlement | All 3 evidence channels deliver matching UTR | First evidence source finalizes settlement; subsequent sources recognize existing finality and record idempotent matching without side-effects. | Database observation log showing deduplication by UTR and release ID. | PENDING BANK UAT | Multi-channel convergence |
| **UAT-012** | Concurrent Payout Attempt | Trigger two concurrent dispatch worker threads for same release instruction | High-concurrency worker simulation | Database row-level locking (`SELECT FOR UPDATE SKIP LOCKED`) ensures exactly one worker thread acquires lease; second worker thread skips. | Thread execution traces, single `SettlementExecutionAttempt` created. | PENDING BANK UAT | Race condition prevention |
| **UAT-013** | Reconciliation Mismatch | Bank statement feed delivers line with altered amount (e.g. ₹7,499 vs ₹7,500) | Statement mismatch simulation | `DeterministicReconciliationMatcher` detects amount discrepancy, marks `UNMATCHED_AMOUNT`, raises operational exception. Ledger is NOT mutated. | Reconciliation run report showing status `DISCREPANCY`, alert generated. | PENDING BANK UAT | Strict ledger discrepancy detection |
| **UAT-014** | Provider Unavailable | Bank API returns HTTP 503 / connection refused | Simulated bank gateway scheduled maintenance | FinX records transport failure, retains message in outbox with backoff, does NOT deduct escrow or finalize. | Outbox message retry count incremented, state remains `PENDING_DISPATCH`. | PENDING BANK UAT | Safe backpressure handling |
| **UAT-015** | Retry After Safe Transport Failure | Socket drops before request headers sent; retry executed with same operation key | Network blip simulation | Second attempt succeeds with original operation key; bank processes single transfer cleanly. | Network error log followed by successful dispatch ACK. | PENDING BANK UAT | Safe retry boundary verification |
